Use `node --import tsx cli/scripts/acceptance/start-load.ts --network /absolute/new-persistent-output` for retained local HTTP soak lanes. The wrapper preserves the caller's `TMPDIR`, freezes the launching revision and refuses a changed or dirty checkout before either lane. Overnight starts only after the hour exits successfully. A scheduled or unfinished lane is pending evidence; failed lanes never count as passes. Require zero errors, completed work drained and owner/worker processes gone before retaining a passing acceptance result. Three completed overnight receipts remain required where the plan calls for three nights; starting this wrapper does not supply them.

Each network lane measures its requested duration after a separate ten-second warmup and thirty-second baseline under the same workload. Read and heartbeat p99 budgets are baseline × 1.25 + 5 ms, capped at half the actual 2,000 ms activity heartbeat timeout (1,000 ms). Insufficient samples, an incomplete window, changed source or an already unsafe baseline fail rather than expanding the budget. Schema-2 receipts retain both windows and their calibration policy. Latency arrays cap each kind at the last 20,000 observations, so long-run p99 certifies the retained tail; cumulative work/errors and post-warmup memory samples cover the full measurement.

The distributed soak workflow is guarded by `BARRY_SOAK_ENABLED` and requires a self-hosted Mac labelled `barry-soak`. Mirror schedules remain pending until that runner is configured; local retained lanes do not require hosted runs. The [trend check](../.github/ci/checks/soak-trend.mjs) strictly validates completed receipts and compares the last five matching platform, hardware, Node, duration, complete workload and calibration-policy receipts against their median. It allows 25% plus 5 ms for p99 timings and 1 MiB/hour for memory slopes; schema-2 comparisons also check baseline read/heartbeat p99 so host load cannot silently raise every budget. Legacy fixed-limit receipts are not interchangeable with calibrated history. A first receipt establishes history; it does not claim a passing historical trend.
