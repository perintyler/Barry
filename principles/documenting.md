# Documentation Principles

Documentation is a human-readable record of domain knowledge.

Its job is to explain:

- what matters
- why it matters
- how to navigate the system at a high level

Documentation is not the place to restate the codebase line by line.

## Prefer

- concise explanations
- decisions, constraints, and terminology
- mental models
- operational guidance

## Avoid

- large code snippets
- implementation walkthroughs of every branch and helper
- repeating details that are already obvious from the code
- bloated reference docs that try to cover everything

## Rule

Write the shortest document that preserves the knowledge another engineer will actually need later.
