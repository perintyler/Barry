# Distributed worker trust

The owner stores workflow history, accepts starts from authorized callers, and decides which worker can claim each activity. A worker runs installed, pinned activity code and returns results. The person holding an invite token can join as that worker: the token is a credential, not proof of machine ownership.

Invite only machines you operate. Job scopes reduce what a credential can claim; they do not verify worker results or sandbox malicious worker operators. A stolen credential can advertise compatible artifacts, claim any job in its owner-recorded scope, read those jobs' inputs, send heartbeats and report fabricated results. Without a scope it can claim any compatible advertised activity. A copied token has the same worker id; the next successful hello takes over its session and fences the displaced process.

## Credentials and enrollment

`barry workers invite <name> --jobs sessions:summarize-session@1,other:job@1` limits a worker to the listed versioned jobs. Omit `--jobs` to allow all advertised activities. The owner checks scope at placement, claim receipt recovery, heartbeat and completion; a worker cannot widen it by editing its token or advertisement. Queue diagnostics use `WORKER_JOB_SCOPE_EXCLUDED`. Revoke and issue a new invite to change scope.

An unused scoped CLI invite expires after 24 hours on the owner's clock. `--expires-in <seconds>` sets an explicit positive whole-second expiry for scoped or unscoped invites. An unscoped CLI invite with no expiry option has no expiry, preserving compatibility with workers on master. The SDK's `inviteWorker` API retains its 24-hour default; an explicit null expiry opts out. Its first authenticated hello marks it joined; the joined credential remains valid until rotated or revoked. `barry workers list` shows pending invites and expiry. `barry workers status` on a joined worker shows the scope recorded when it joined. The owner remains authoritative if the worker's local display was changed.

Tokens without scope or expiry use `barry_wj1.` with exactly master's original fields. Tokens carrying scope or expiry use `barry_wj2.` and require a worker that supports version 2. Version 1 tokens remain accepted for unscoped, nonexpiring invites, and joining one prints a compatibility notice. Existing workers from before this migration retain their unscoped authority and have no retroactive unused-invite expiry. Rotation preserves the worker's scope and expiry policy, so rotating an unscoped nonexpiring worker also emits a version 1 token.

The owner keeps a hash of each `barry_wk_` credential in `peers.db`; the worker stores the outgoing credential in its private credentials directory. That credential opens only `POST /api/worker`. It opens no console, run inspection, start, session, identity or store API. The authenticated worker `probe` operation returns owner identity without opening a session, consuming an unused invite or adding a join/takeover audit; doctor uses it to check a link safely. The service's operator secret and actor credentials are separate authorities and are never sent to a worker. Rotate keeps the old credential valid for five minutes, measured by the owner's clock. Revoke immediately refuses subsequent authenticated requests; a running effect is aborted when the worker next learns of the refusal, and its lease expires for retry.

The owner's `peers.db` stores audit rows for invite, first hello (join), rotation, revocation and session takeover. Each row contains worker id, owner-clock time and caller (`local-operator` for local CLI operations, authenticated worker id for hello). `barry workers list --json` includes the rows. These rows contain no tokens or job inputs. A takeover is recorded even if no activity was outstanding. Peer enrollment/credential mutations and their audit rows commit atomically in `peers.db`; an audit refusal also rolls back the associated workflow session change, leaving the previous session and attempt live. The workflows database and `peers.db` are separate transactions: hello audit rows record authenticated enrollment intent, and a subsequent workflows commit failure can leave an intent without a committed session change. Reconcile with workflow session/history records when interpreting a takeover. This is an operational enrollment history; protecting the database and its backups remains an operator responsibility.

## Network exposure and data

A publicly reachable `workflows.runtime` also exposes the console and its sign-in page. Use a private HTTPS route; a worker credential alone does not make the route private. Interactive tunnel login gates prevent unattended worker calls and are refused by invite address discovery.

The owner sends the worker only the activity input, pinned artifact identity, logical effect key, attempt identity and relative execution/heartbeat budgets. It never sends Barry secrets, files, sessions, identities, store copies or operator credentials. Inputs can still contain sensitive application data: choose scopes and inputs accordingly.

Only versioned Node jobs bounded to no files and declaring no secrets are remotable. Remote action jobs require the caller's grant and pinned prompts; remote jobs with files or restricted network need a containment mechanism able to express those bounds. Both remain unsupported. Worker wall-clock skew does not decide attempt deadlines: the owner uses its clock, and workers use relative monotonic budgets.
