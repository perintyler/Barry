# Artifacts

An artifact records a generated file at a point in time. Its original bytes, filename, MIME type, hash and creation provenance stay fixed. Titles and tags can change with an expected metadata revision.

The public package exports are:

- `@barry-rocks/artifacts-bag`: Node `withArtifactStore` resolves the current Barry identity/binding for each invocation and closes its owned connection.
- `@barry-rocks/artifacts-bag/migrations`: shared SQL history; execution remains adapter-owned.
- `@barry-rocks/artifacts-bag/contracts`: runtime-neutral schemas and errors.
- `@barry-rocks/artifacts-bag/core`: authorized read, list and metadata operations with injected adapters.
- `@barry-rocks/artifacts-bag/create`: authorized streamed creation with injected storage, clock, IDs and fingerprint hashing.
- `@barry-rocks/artifacts-bag/blobs`: runtime-neutral blob contracts and the 25 MiB limit.
- `@barry-rocks/artifacts-bag/local/blobs`: durable filesystem CAS beside the selected database.
- `@barry-rocks/artifacts-bag/local/maintenance`: bounded cursor-based intent recovery, coordinated collection and content reconciliation.
- `@barry-rocks/artifacts-bag/local/catalog`: identity-bound SQLite catalog using an explicitly supplied `better-sqlite3` connection.

Contracts and core load no Node modules or Barry installation discovery. Access adapters must verify the current credential, required scope and identity on every call. Creator provenance does not grant permission. Read/list operations recheck the original credential after loading data; metadata changes recheck it before the synchronous transaction.

Catalog initialization records its owning identity and refuses another identity. Maintenance also binds the exact database/sidecar and checks file identity plus an immutable catalog generation token; replacement stops cleanup. Active-generation restore/cutover integration remains registry work. SQL triggers protect content/provenance and catalog ownership, including replacement inserts. Metadata changes require the next revision. Catalog transactions use `BEGIN IMMEDIATE`, roll back on failure, reject caller-owned transactions and asynchronous callbacks, and invalidate retained transaction objects after use. The caller owns and closes the database connection.

Lists sort by descending `(createdAt, id)` with bounded cursor pagination. Search matches literal filename, title, kind and tag text, including literal `%` and `_`. A full page supplies a next cursor; following the final full page can return an empty page.

Creation records a two-minute durable intent, streams at most 25 MiB into exclusive staging files, snapshots each producer-owned chunk, hashes and syncs the bytes, and publishes with a no-clobber hard link. Existing equal-content blobs must verify their hash and size. Staging and blob directories have mode `0700`; published files have mode `0400`. Files and affected directories are synced before publication succeeds. SQLite uses WAL with FULL synchronous commits. Catalog records and retry results commit only after publication and a final credential/session authorization check. Creation checks its 60-second monotonic deadline after acquiring the catalog lock and before commit. A supplied originating session requires an injected verifier; lineage requires a parent in the same catalog.

Matching identity-scoped idempotency keys return their original artifact; changed bytes, original metadata or actor provenance conflict. Distinct events can share bytes while retaining distinct artifact IDs. Failed writes and crashes retain durable intents for later reconciliation. Completed creations survive staging-cleanup failures. The local maintenance API reaps expired known staging intents and collects verified unreferenced bytes after a ten-minute grace period. Durable deletion markers block publication for the affected hash. References, leases and persistent backup pins are checked under the SQLite writer lock; verified physical deletion and catalog acknowledgment share that lock. An interrupted deletion is safe to repeat. Published records remain untouched. Cleanup preserves corrupt and unknown files and reports referenced missing/corrupt bytes. Persistent cursors continue work across worker restarts, with at most100 entries per lane and a cooperative time budget (200ms by default). Kernel/SQL stalls can exceed that cooperative budget and remain infrastructure validation work. The daily `artifacts/maintenance` schedule runs this API for existing active identity stores. It preserves the ten-minute grace period and the per-store bounded work budget; failed or sealed stores are reported without blocking maintenance of other identities.

`artifacts.web` serves `/health`, public `/p/…[/raw]` share links, and the owner artifacts API authenticated with a bearer `BARRY_SECRET` or a signed-in browser. The tools build links from the service registry. HTTP uploads answer 503.

Run `pnpm --dir bags/artifacts test` and `pnpm --dir bags/artifacts build` from the repository root.

The manifest declares one identity-owned SQLite store, normalized to `default`. `withArtifactStore` uses Barry's current store binding: managed paths follow the active registry root, explicit absolute filepaths remain exact, and missing identities or unsupported remote URLs fail without a node-store fallback. `openLocalArtifactStore` accepts an explicit trusted binding for server construction. These storage ports do not authorize public requests; create a core/creator with a verified access adapter.

Local and registry-created catalogs use Barry's checksummed `schema_migrations` history and `user_version`. Initial artifact catalogs are adopted without deleting their records or changing the generation; unsupported schemas are refused. The generic SQLite snapshot provider refuses stores declaring required companion resources. `loadDeclaredStores(registry, bags)` loads the declared `snapshots.default` compiled hook automatically, including in the normal node, schedule and CLI store-loading paths. Programmatic hosts that register stores themselves can use `registerArtifactSnapshots(registry)`. The hook is a trusted local bag module, separate from the SQL migration declaration; peers cannot select executable providers through snapshot metadata. It captures a consistent catalog, pins its referenced hashes, copies independently verified bytes, and writes a catalog-bound resource index. Registry snapshots and backup creation retain and verify that complete unit, including empty files and deduplicated content. `store.snapshot(destination)` also supports an explicitly configured local catalog path. Pins are released after capture or an ordinary failure; process crashes retain pins for explicit recovery. `barry db restore` restores the catalog and its companion bytes into a new store generation through the bag's `restores.default` hook. Crash-pin recovery remains open; registering only the generic SQLite declaration without its declared hook still refuses artifact capture.

`prepareLocalArtifactRestore` from `@barry-rocks/artifacts-bag/local/restore` is a trusted operator API that builds a private candidate from a verified snapshot. It checks the exact supported schema and identity, rejects unclassified tables/columns, preserves immutable records, mutable metadata, lineage and idempotency results, verifies referenced bytes, and mints a fresh storage generation through the canonical migrations. It retains diagnostic intent rows while expiring their old leases and failing unfinished uploads, omits old pins/deletion gates/cursors, and writes a synced `restore.json` preparation record. The source backup and current catalog remain untouched.

`activateLocalArtifactRestore(prepared, binding, { servicesStopped: true, expectedGeneration })`, from the same export, performs an exact-path cutover. Prepare the candidate on the destination filesystem, stop and drain affected services/connections, and supply the outgoing generation token. A private SQLite operator lock serializes cutovers and releases on process death. A synced `<filepath>.activation.json` journal blocks normal catalog/store/blob reopening during the handoff. The operator seals the outgoing catalog, drains WAL and switches it to rollback journaling before moving the catalog and sidecar into `<filepath>.previous-<activation-id>/`. It then installs the prepared pair at the exact binding path, rechecks SQL integrity, schema/ownership/tokens and every referenced content hash, records the preserved history, and marks the handoff active. Retry the same candidate/binding/token to resume an interrupted handoff. A failed handoff stays blocked until recovery; it never unseals the old generation or deletes history. Normal store opening returns the new catalog to WAL mode after activation. This trusted lower-level API requires caller-enforced service shutdown; global generation-selector activation and generic backup restore/CLI integration remain required work.

`sealArtifactGeneration(database, identityId, expectedGeneration, sealedAt)` from `@barry-rocks/artifacts-bag/local/catalog` permanently seals an outgoing catalog under a SQLite writer lock. It checks ownership and the unchanged generation token; repeated calls retain the original sealing time. SQL triggers reject subsequent catalog, intent, pin and maintenance writes, including through retained connections. Repository writes, blob operations and maintenance also reject sealed generations. Historical catalogs remain readable through the catalog repository; a verified sealed snapshot can produce a fresh writable restore candidate. Operators must stop and drain writers before sealing and changing selection.

A share password goes in the `X-Artifact-Password` header, and the public preview describes only the file. Preview and HEAD requests read metadata without opening the blob stream. Download streams close their file handles on completion, cancellation, request abort or read failure; callers that abandon a blob iterator must call its `return()`.

The local installation secret (`BARRY_SECRET`) grants full artifacts API access across the installation. Identity IDs in URLs select resources; they do not authenticate separate tenants. The default local actor and credential labels are provenance, not an additional authorization boundary. Remote actor/credential machinery remains dormant until a remote deployment has its own enforced authorization contract. This review does not depend on or land PR #56.

Share updates through `ArtifactHttpClient.updateShare` require `artifactId` alongside `shareId`; the artifact ID routes the request and is omitted from the update body.
